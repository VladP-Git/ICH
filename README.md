# ICH



# Фильмотека Sakila — Поисковая Система

Учебный проект по разработке приложения для поиска информации о фильмах с использованием обезличенных данных. Проект объединяет фронтенд-технологии и гибридную бэкенд-архитектуру на базе реляционной (SQL) и документоориентированной (NoSQL) баз данных.



## Цель проекта
Создание веб-интерфейса, заменяющего стандартный консольный ввод, для удобного поиска кинокартин, фильтрации по жанрам/годам и логирования пользовательской активности.

##  Стек технологий
*   **Frontend:** HTML5, CSS3, Bootstrap 5 (компоненты карточек, адаптивная сетка, кастомные visually-hidden лейблы для Accessibility).
*   **Шаблонизатор:** Jinja2 (динамический рендеринг, интеллектуальный скользящий диапазон пагинации `< 1 ... 50 ... 101 >`, динамические списки).
*   **Backend:** Python 3.14 (FastAPI + Uvicorn), профилирование времени выполнения запросов СУБД с помощью модуля `time`.
*   **Реляционная БД:** MySQL (удаленная база данных Sakila), использование параметризованных запросов (`%s`) для защиты от SQL-инъекций, оптимизация дубликатов через `DISTINCT`.
*   **NoSQL БД (Аналитика):** MongoDB (локальный сервер MongoDB Community Server), администрирование через MongoDB Compass. Использование мощного конвейера агрегации (`Aggregation Pipeline`) для фильтрации, группировки и сортировки Топ-5 запросов.
*   **Управление версиями:** Git / GitHub (с разделением на публичный репозиторий кода и приватный для учебных материалов).

##  Реализованные архитектурные фичи (MVP+)
1.  **Автономность фронтенда:** Все файлы Bootstrap и Bootstrap-Icons переведены на локальное хранение в каталог `static/` для обхода тайм-аутов внешних CDN-сервисов (jsdelivr/cloudflare).
2.  **Умная пагинация:** Реализован постраничный вывод фильмов (по 10 штук на страницу) с автоматическим сохранением GET-параметров поиска в URL. Ряд страниц автоматически сжимается с использованием многоточий `...` при больших объемах данных.
3.  **Защита аналитики:** Логирование в MongoDB срабатывает строго при инициализации нового поиска (`page == 1`), исключая накрутку счетчиков при простом перелистывании страниц пользователем.
4.  **Безопасность соединений:** Коннекты к СУБД обернуты в безопасные конструкции `try/finally` с предохранительной проверкой инициализации переменных (`if client is not None:`).
5.  **Декоратор:** Использование `@log_search` для NoSQL.
6.  **Централизованная отказоустойчивость:** Реализован глобальный перехватчик исключений Global Exception Handler. При любых критических сбоях (например, недоступности базы данных MySQL) приложение не падает, а автоматически изолирует трейсбек ошибки в журнал `app.log` и выводит пользователю дружелюбную Bootstrap-страницу вместо стандартного белого экрана.


Запуск и отладка сайта выполняется при помощи бэкенд-сервера на Python — файл backend/main.py. Сервер компилирует страницы и отдаёт их браузеру.


# Алгоритм запуска:
1. Запуск сервера в PyCharm:
    В терминале PyCharm (должен присутствовать префикс (.venv)) нужно ввести команду запуска главного файла:
    python backend/main.py

2. Открытие ссылки:
    В консоли появится лог запуска FastAPI, где будет написан постоянный адрес. Достаточно удерживая клавишу Ctrl кликнуть мышкой по этой ссылке в терминале:
    * Running on http://127.0.0.1:5000
    * Либо ввести в адресной строке браузера Хром вручную: http://localhost:5000

Отладка «на лету» (Live Reload):
В файле main.py включен режим отладки (reload=True), как только будут внесены изменения в код Python или в HTML-шаблон, сервер FastAPI в терминале сам мгновенно перезагрузится или по нажатию Ctrl+s. Достаточно будет просто обновить страницу в браузере (F5), чтобы увидеть изменения.

## Автоматическое тестирование (QA)
В проекте реализовано автоматическое модульное тестирование бизнес-логики с использованием фреймворка `pytest`. Тесты изолированы от баз данных, параметризованы и проверяют критические узлы веб-приложения:
*   Очистку поискового текстового запроса от невидимых символов и пробелов (`.strip()`).
*   Срабатывание триггера и флага пустого поиска при вводе одних пробелов.
*   Правильный расчет лимитов пагинации в зависимости от выбранного режима сетки (`strict`/`adaptive`).

### Алгоритм запуска тестов:
1.  Убедитесь, что в вашем виртуальном окружении установлены необходимые библиотеки (указаны в `requirements.txt`):
    ```bash
    pip install pytest
    ```
2.  Запустите тестовый движок из корня проекта `movie_search_project\tests` командой:
    ```bash
    pytest -v 
    ```
Сервер автоматически подхватит конфигурацию `conftest.py`, выполнит все проверки и выведет отчет в консоль.

## Автоматическая генерация документации (QA / Инспекция кода)
В проект интегрирована служебная консольная утилита `doc_viewer.py`, предназначенная для мгновенного извлечения и презентации стандартизированных докстрингов (Google Style) прямо в терминал. 

Утилита автоматически изолирует область видимости инспектируемого файла, отсекая сторонние импорты и скрытые маркеры кодировок (Windows BOM).

### Алгоритм запуска инспектора документации:
Запуск выполняется из корня проекта `movie_search_project/` при помощи вызова утилиты с указанием целевого модуля в качестве аргумента:

*   **Инспекция бизнес-логики (`backend/funcs.py`):**
    ```bash
    python doc_viewer.py funcs
    ```
*   **Инспекция разработанных модульных тестов (`tests/test_funcs.py`):**
    ```bash
    python doc_viewer.py test_funcs
    ```

Движок самостоятельно просканирует каталоги приложения, динамически импортирует нужный скрипт и выведет структурированное описание модуля и всех его внутренних функций.
